## Interaction Contract

### Admin Status Selector (dialog view, admin role only)

- Rendered as a `<select>` element in `.fs-admin-status`, positioned below the suggestion type/status badge row and above the details text
- Label element with `for` attribute wired to select `id` — renders as "Update Status" at 14px / weight 500
- Immediate-action pattern: change event persists on select; no separate save button
- Loading state: set `disabled` attribute on select while `setStatus()` is in flight; restore to enabled on resolve/reject
- On success: update `suggestion.status` in local state; re-render feed card badge and dialog badge without page reload
- On error: re-enable select, restore prior selected value, display inline `.fs-admin-error` message: "Couldn't save status. Try again." (14px, #dc2626, no background — inline text only)

### Status Badge (all users, card and dialog)

- Renders only when `suggestion.status` is a non-empty string
- Position on card: second badge in `.fs-card-header`, after `.fs-card-type`
- Position in dialog: second badge in the badge row, after type badge, before details
- Apply the Status Badge Semantic Color Map — each status has a unique background/text pairing
- CSS class: `.fs-card-status--{status-slug}` (e.g. `fs-card-status--in-progress`) applied alongside base `.fs-card-status`
- Badge text: exact stored status string — no transformation, no truncation

### Focal Points

- **Admin view (dialog open):** "Update Status" select is the primary admin interaction point — placed before the details body to ensure discoverability without scrolling
- **All users (feed view):** Colored status badge is the secondary visual anchor on each card — color contrast draws attention after the title
